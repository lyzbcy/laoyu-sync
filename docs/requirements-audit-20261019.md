## 范围与结论

依据 `E:/共享/tools/软件开发` 中全部 Markdown 规范，包括启动器适配 Skill 及其适配规范。检查本机 0.3.12 候选源码、Windows 最终包、上一轮双平台 CI、0.3.11 正式发布对应 CI 的原生验收证据，以及本机软件中心源码登记。

不能判定为“全部符合”。反馈界面存在，但干净配置的候选包及正式 0.3.11 对应 CI 包没有反馈渠道；更新器的 Mac 一键安装、旧版本备份清理、镜像测速也尚未完整实现。日志、双平台构建、软件内推广、主程序身份、更新校验与用户数据隔离已有实现证据。

版本必须区分：

- 远端正式版本为 **0.3.11**。本机候选源码为 **0.3.12**，对应 PR #1、提交 `8cff1845bd1acda77895abc589459c45a23ad64d`，未推送正式更新渠道。
- 本机根 `launcher-adapter.json` 和 `version.json` 仍为 0.3.9；本机软件中心源码 catalog 的 Sync 静态回退为 0.3.1。它们属于本机过旧登记，不能据此断言远端正式更新清单或所有已安装软件中心客户端也为旧版。
- 0.3.12 候选未正式发布是既定交付状态，不应通过把正式清单提前改成 0.3.12 来“修复版本不一致”。

## 可操作的缺口

### F1 — P1：最终包反馈渠道没有注入

证据链：

1. `core/config.py:25` 默认 feedback_url 为空；`:79` 仅从已配置值或外部/包内 feedback-channel.json 读取，无规范缺省渠道兜底。
2. `LaoyuSync.spec:15` 只有构建时设置 LAOYU_FEEDBACK_CONFIG_PATH 才收集渠道配置；`.github/workflows/build.yml` 没有注入步骤，且原生验收显式允许未配置渠道。
3. 0.3.12 Windows ZIP 中无 feedback-channel.json；独立观察提交反馈 disabled=true。
4. 0.3.12 本机原生验收与正式 0.3.11 对应 CI run 39193880457 的原生证据都记录 `feedback_url_configured: false`。

影响：干净配置的用户即使看到反馈表单，也不能一键发给作者；已有用户若自行配置了渠道不在这个断言范围内。0.3.3 历史真实发送成功不能代替当前包验收。本轮未重新下载全部正式二进制；正式版本证据来自对应 CI 原生 artifact 和正式发布文档关联关系。

建议：使用已有指定渠道，按构建注入方式配置；正式包验收应在预期配置渠道时拒绝缺失配置，不能一律允许。检查包内实际配置及 /api/meta 后，再在获得发送授权的流程中验收文字/附件业务回执。审计报告不记录 webhook 值，本轮没有发送外部消息。

### F2 — P2：Mac 没有一键更新安装

`core/updater.py:110` 的 start() 仅支持 Windows 冻结包，Mac 返回去发布页下载的错误。符合“可检查/手动下载”，未达到规范对所有支持平台的一键更新、自动重启期望。需单独实现并实机验证 Mac 安装替换、重开、数据保留和回退；不能移除平台保护伪装完成。

### F3 — P2：旧版本备份不会自动清理

`core/updater.py:237` 创建 `.previous-*`，成功回执保存 backup；`core/update_cleanup.py:135` 只遍历 `.laoyu-update-*` 暂存目录，不清理 `.previous-*`。现状文档也明确保留旧版备份。下载暂存的安全清理已有实现，但不等于“新版确认可用后清理旧版本”全部完成。

建议在可验证健康确认、回退窗口结束、无占用且身份文件不在范围内时，按明确策略回收旧版；不能直接全盘删除同名前缀。

### F4 — P2：缺少下载线路测速与选择

`core/version.py:83` 和 `core/updater.py:149` 使用固定可信 GitHub 清单/下载地址，没有候选线路测速、选择最快线路或镜像回退。国内代理提醒与失败重试已存在，不能替代规范第 6 条。建议复用受信任线路方案，下载后仍校验原始包哈希，不能随意放开第三方镜像。

### F5 — P2：本机启动器发布登记不一致，严格自查未通过

- 原根描述文件检查：22 PASS / 6 FAIL，退出码 1；本机 0.3.9 ZIP 缺失，并与本机中心源码 catalog 发布字段不一致。
- 针对真实 0.3.12 ZIP 生成隔离候选描述文件后：31 PASS / 5 FAIL，退出码 1；本地包哈希、1200 条目、展开 104045209 bytes、根主 exe、路径安全和真实 ID/portable 映射通过；5 个失败均为与本机中心源码 catalog 的版本、哈希、URL、资源名等发布登记不一致。
- 隔离候选描述的 0.3.12 URL 是待发布目标；自查只验证结构，没有验证该 URL 已公开。不得把这份报告作为已发布证明。

建议正式发布时同步对应包、描述文件与中心下载记录；旧/新客户端安装识别、从中心点击打开及更新后仍识别分别验收。本轮未修改中心，也未断言所有安装客户端都失败。

### F6 — P2：本机文档与版本基线过期

README 仍有“正式发布版仍为 0.3.2”，SKILL 当前正式版写 0.3.9，旧审计日期 2026-10-01，updater/testing 部分摘要仍为 0.3.2/0.3.0。实际远端正式为 0.3.11，候选源码为 0.3.12。远端主分支 SKILL/元数据已有部分更新，本机脏工作区未自动覆盖；这是本机接管基线问题，不把它当成远端发布包版本错误。

建议统一“正式/候选/历史”说明，给模块文档补齐现状、负责人、更新时间；保留历史证据但不要让旧摘要充当当前结论。本报告与旧审计的最新指向用于防止继续误读。

### F7 — P2：求好评弹窗没有真实评价直达

`ui/app.js:876` 的 showReview() 只提供“去点 Star”。反馈分类有“建议与评价”，但弹窗未提供直接写评价的入口，且 F1 导致普通评价也无法直达。可在同一弹窗提供简短真实评价入口，复用反馈表单/接收确认和 15 天免打扰，不新增跳转负担。

### F8 — P3：反馈分类下拉样式未统一

`ui/style.css:234` 统一了 input/textarea，只有新同步网络 select 单独有主题样式；反馈分类下拉仍为原生样式。独立截图目视可复现，属于低优先级视觉一致性缺口。
