## 0.3.13 当前实现

版本源 core/version.py；正式更新清单 version.json 保留旧 Windows download_url/sha256 字段，并提供 platforms 分平台资产。先公开校验最终资产，再切换正式清单。候选源码和本地包不等于正式发行。

每天按 UTC+8 检查，尝试/成功分别记录；手动可重试。只比较正式 x.y.z 数值，忽略同版/降级/预览版。清单从固定 GitHub TLS 地址读取；Mac 按 arm64/x86_64 选择对应资产，缺失时拒绝使用 Windows 包。

下载由 download_routes.py 并发探测 GitHub、ghfast.top 与 gh-proxy.com 的固定发行 ZIP 路径；每条最多16KB、4秒，拒绝HTML挑战页，按有效样本时间排序。下载失败或 SHA-256 不符尝试下一条，每次清空自己的部分文件；全部失败保留原应用并提供重试/发布页。镜像不提供可信清单；哈希始终来自 GitHub 正式元数据。更新请求沿用原网络/代理，同步优先直连只控制引擎。

Windows 沿用完整 ZIP 和独立 helper：校验、等待旧进程退出、保留卸载器、原目录备份、新版可见窗口+renderer/engine ACK、登记更新版本；失败清理新进程树并恢复原目录。

Mac 使用 updater_mac.py：新 ZIP 必须只有 LaoyuSync.app（忽略 AppleDouble 元数据），先解压普通文件，再创建仅指向包内的链接；拒绝通过链接写文件、重复/越界路径、特殊设备文件及错误身份/版本。保留可执行权限并运行 codesign --verify --deep --strict。助手从同级暂存运行，随机 ready 令牌确认后才退出原应用；旧进程退出后原 .app 备份并原位替换，直接启动真实应用，等待可见窗口/renderer/引擎确认；失败结束新进程组、恢复原 .app 并重新打开。

清理由 update_cleanup.py 负责。完成事务保留证据后回收暂存，活动新版仅保留的健康 ACK 参数不应永久阻止下载包回收。旧版备份只有健康成功回执，且过24小时回滚窗口、当前版本达到目标、文件哈希/路径/数据归属/进程占用核验都通过才回收。拒绝无凭据旧目录、身份文件、越界链接、无法读取进程和仍需恢复的事务。

Mac 0.3.11 及更早版首次需要手动安装一次带更新器的新版；Windows 0.3.6/0.3.7 的旧 helper 有既有文件占用缺陷，首次也需完整安装修复版。源码环境永不覆盖当前 checkout。

核心验收：tests/test_release.py、test_update_transaction.py（Windows）、test_mac_update_transaction.py、test_standards_fixes.py、test_update_history_cleanup.py；真实冻结包用 scripts/verify_update.py 和 scripts/verify_macos.py 验成功/故障回退。每次区分单测、同版本真实事务、跨版本安装和公网客户端完整更新链路，不互相冒充。

## 0.3.4：历史结果与暂存清理

结果增加目标版本、旧版本、结束时间、目录。当前运行版本达到失败目标且确已跨过旧版时，将原始JSON按内容哈希归档到用户数据update-history，保留归档原因；没有版本的旧失败作为历史归档。有recovery的记录不隐藏，同版失败也不冒充升级成功。新尝试归档原记录，不删除历史。

更新助手结束后写cleanup-ready.json，和transaction.json交叉核验。同步助手及软件中心共用schema=1/product=laoyu-sync协议，启动后及每120秒尝试清理。只有已完成/已回滚/已被新版取代的.laoyu-update-*直属目录可清理；凭据至少60秒，相关PID、可执行路径或命令行仍占用则跳过；进程查询失败也跳过。拒绝链接/目录连接、越界/配置目录位于暂存内、未完成及恢复失败目录。删除前再次检查路径，并将事务/完成凭据存到同级.laoyu-update-history；不删除.previous-*备份、安装目录、用户配置、日志和同步身份。

旧无结束凭据的暂存，只有事务创建超1小时、旧安装目录已不存在（或旧助手留下目标版本的完整窗口+引擎ACK）、当前运行版本不低于事务目标且相关进程已退出，才能标记为superseded。旧目标仍存在或证据不足则保留。开发回归全部使用隔离目录，不操作真实用户同步。
