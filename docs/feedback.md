# 用户反馈

现状：0.3.3按用户明确要求直发企业微信，开发、真实附件与最终EXE渠道识别验收通过。负责人：捞鱼工作室。最后更新：2026-10-01。

用户明确要求不使用现有/自建服务器，所有反馈通知统一向提供的企业微信机器人发送；此要求优先于之前中转设计。已移除未部署server代码与配置，不再需要SSH。

一级侧栏“遇到问题反馈”，可选分类，备注最多4000字；日志默认勾选、可取消、可预览。版本/系统/分类/编号随文字发送，勾选日志则将脱敏诊断和完整留言打成ZIP，用企业微信官方webhook/upload_media?type=file上传，再用机器人file消息送到同一个群。不读取同步文件，不经过捞鱼服务器。日志从企业微信群下载；这是按用户本次指示对原“长链接日志”要求的附件替代，不声称自建七天链接仍适用。

每次请求核验企业微信errcode=0，HTTP200不代表成功。上传失败不发留言；留言确认但附件失败明确提示部分完成，保留输入，重试只续发未确认步骤。随机request_id和本机最近20条进度记录防双击/成功后的重复提交；网络响应丢失时无法保证机器人未接收，因此不自动重试。文字按UTF-8字节分段，每条低于官方2048字节上限，不截断长中文备注。临时media_id有有效期，进度保留2天。

机器人链接作为仓库外feedback-channel.json注入构建，PyInstaller资源中读取，空旧配置自动回落至包内配置。不进入公开Git源码/用户日志，但含该配置的安装包能够被提取；这是用户要求预配置直发的固有限制，已告知。无配置或错误URL禁用/拒绝提交，不冒充发送。

45项隔离测试通过，含取消日志/业务拒收/ZIP/部分失败续发/重复提交/中文长文/错误地址/脱敏。真实机器人上传日志+文字+附件三阶段均成功，verification/direct-feedback/real-wecom-result.json；测试日志为合成数据，没有发真实用户日志。官方协议依据：https://developer.work.weixin.qq.com/document/path/91770。
